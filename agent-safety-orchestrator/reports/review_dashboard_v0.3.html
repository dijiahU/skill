📖 卡片上的 badge 含义（点击折叠）

① enforcement_mode（贴在每个 atom 卡片头）—— 这个原子的强制方式，是 v0.5/v0.6 包装的"第一刀"。决定该原子最终是落进 hooks/ 还是 SKILL.md。

Badge含义典型实现
🔒 hookhost 硬强制，agent 无法绕过regex / OS config / 签名校验 / 日志写入 / counter 阈值
🧠 skill需要 agent LLM 语义判断；通过 SKILL.md 内的 tool 调用意图比对、攻击树生成、威胁清单分析
⚡ hybridhook 快速通道 + LLM 语义 fallback（hook 抓不住的复杂 case 升级给 LLM）带模糊语义的 jailbreak 检测、unsafe-deser 跨语言变种、CI workflow 审计

② archetype packaging（贴在每个 archetype 折叠头）—— 由该 archetype 内部 atoms 的 enforcement_mode 分布决定 archetype 最终怎么出货。

Badge含义出货
pure 🔒 hook所有 atoms 都是 hook 模式不出 SKILL.md，所有 atom 直接进 hooks/ bundle（agent 无需路由调用）
pure 🧠 skill所有 atoms 都是 skill 模式（v0.6 已无此情形）1 个完整 SKILL.md，内部所有 tools 都需要 LLM 推理
mix: M 🔒 + N ⚡ + K 🧠跨多种 enforcement_mode（混合）1 个 SKILL.md（含 skill/hybrid tools）+ hook 部分进 hooks/

③ execution_type（贴在每个 archetype 折叠头，仅对 SKILL.md 出货的 archetype 有意义）—— SKILL.md 内部的 skill/hybrid tools 怎么协调。是 v0.4 引入的次要维度，告诉 agent "我读这个 SKILL.md 时是按啥模式去依次调内部 tool"。

Badge含义典型场景
🔄 workflow顺序执行，后步依赖前步classify-input-intent-ambiguity（先 classify → 再 ask clarification）、incident-response-handler（halt → snapshot → isolate → notify → recover）
☑ checklist并行 fan-out，互相独立detect-prompt-injection（5 种 injection 类型独立检测）、validate-tool-argument-safety（8 种参数风险并行扫描）
🔀 mixed先并行 detect，后串行 enforcescan-input-for-pii-and-secrets（先并行检测 5 种 PII → 后串行 redact）、enforce-rate-and-quota-limits

完整定义见 SAFETY_ATOMIC_CAPABILITIES.md §10.1（enforcement_mode）/ §10.2（archetype packaging）/ §10.4（execution_type）。
